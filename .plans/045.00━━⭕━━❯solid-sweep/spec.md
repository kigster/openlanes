# SOLID Sweep

Source: GitHub issue #95 (S19), rescoped on 2026-10-24 by `docs/decisions/decisions-on-dry-rb-architecture.md` (A1, A2, A8 to A13, and "What earlier plans already settled").

## What we are trying to achieve

A codebase that reads crystal clear, wired as a dry-rb application, with no change in behaviour.

- dry-system registers every component from `lib/` through the existing Zeitwerk loader; collaborators arrive by `Deps[...]`; providers own Redis, GitHub, Linear, the event bus, the logger and OpenTelemetry (A1).
- Coding agents are components under `adapters.<name>`, resolved by name; the hand-written registry hash goes (A2).
- Every class at most 100 lines, every method at most 10, at most 4 parameters, AbcSize at most 20, enforced by rubocop with no exemptions left. Metaprogramming only where it declares: `Data.define`, class-level DSLs, `def_delegators`, `define_method` over a literal list, and `inherited` or `included` hooks that set per-class instance variables (A8).
- Behaviour is frozen: CLI flags and output, `.plans/` files and API responses unchanged, existing spec assertions untouched (A9).
- The bare `Thread.new` sites move to concurrent-ruby; fallible operations return dry-monads `Result`; a vendor-neutral `Judgment` port, with Jev only when `TYPESAFE_API_KEY` is set (S15, S19).
- Logs and traces from one set of dry-monitor instrumentation events: SemanticLogger to `log/openlanes.log`, and spans through `opentelemetry-api` only (A13). Spans are new behaviour and land in their own pull request.

## Why it matters

`engine/dispatcher.rb` is 2,671 lines with 142 methods, and 58 classes exceed the 100-line limit that `.rubocop.yml` already states. Tasks (053.00), `ol new` (054.00) and `ol init` (055.00) all build on swappable components that do not exist yet.

## What already exists

- The `038.00` seams: `EventBus`, `Clock`, `Process`, the adapter capability contract.
- Facades per namespace; dry-monads and concurrent-ruby in the gemspec; the `Engine::Upkeep` facade from #127 as the pattern for a split.
- `ol uml` and the frozen `docs/architecture/before/` snapshot (052.00), regenerated by every pull request here.
- The global lock (034.00): this plan runs alone.

## What research needs to settle

- The seam order after Dispatcher, Executor, PlanState and RunWorkflow (A11 says the rest by size).
- How dry-system's component dirs map onto the Zeitwerk-collapsed `support/` and `cli/<command>/` directories.
- Which of the 24 `Thread.new` sites need a pool and which a `TimerTask`.

## Framing

- **A. Big-bang rewrite**: one pull request restructures everything. Rejected: unreviewable at 524 todo entries, and A11 forbids it.
- **B. Metrics-driven shrink**: take files off `.rubocop_todo.yml` until `Metrics/*` has no entries, wiring dry-system as each seam is cut. One seam per pull request (A11).
- **C. Wiring first**: finish dry-system and providers, split classes later. Rejected as the lead: it leaves the 100/10/4/20 limits unenforced for longest.

**Chosen: B**, with the providers (C's content) cut first as the first seams, because the rubocop todo list is the only objective, checkable measure of "done" and each pull request can shrink it.

## Goal

After this plan ships, every class in `lib/` fits the A8 limits (class ≤ 100 lines, method ≤ 10, ≤ 4 parameters, AbcSize ≤ 20) with `.rubocop_todo.yml` holding no `Metrics/*` entry, collaborators arrive through `Deps[...]`, providers own Redis, GitHub, Linear, the event bus, the logger and OpenTelemetry, coding agents resolve by name as `adapters.<name>`, and the 29 bare `Thread.new` sites run on concurrent-ruby. Tasks (053.00), `ol new` (054.00) and `ol init` (055.00) can then swap components instead of editing 2,500-line classes. Nothing a user sees changes, except new log file and spans delivered in their own pull request.

## Non-Goals

1. No behaviour change in a restructuring pull request (A9): CLI flags and output, `.plans/` files and API responses stay byte-identical.
1. No new commands, states, flags or agents.
1. No change to the state machine topology or to `Status` vocabulary.
1. No vendor tracing gem; only `opentelemetry-api` (A5, A13).
1. No rewrite of `spec/` assertions; specs may move with their class and gain examples only.
1. No touching `docs/architecture/before/`, which is frozen (A10).
1. No tasks, `ol new`, `ol init`, Leah (A7) work: those are 053/054/055 and earlier plans.

## Out of scope

- Tasks, `ol new`, `ol init`, planner dependency resolution: separate plans (053 to 055), which need this one first.
- Spec rewrites: A9 freezes assertions.
- Choosing an OpenTelemetry SDK or exporter: users add them (A13).
- Merging: only the maintainer merges (A11).
- Linear/GitHub behaviour changes: the seams are rewired, their contracts are not.

## Back end / front end

This is a CLI gem; there is no front-end half of the refactor.

- **backend-coder:** every in-scope item above.
- **frontend-coder:** only keeps the web page building: `web/demo.rb:66` and `web/context.rb:87` hold `Thread.new` sites in the server side and belong to backend-coder; the front end (`web/`) takes no change, and its e2e job in `.circleci/config.yml` is the check that nothing moved.

## Risks to planning or execution

- **Size.** 524 todo entries across all cops; the Metrics ones touch most of `lib/`. Planner should cut by seam, not by file kind.
- **Merge conflicts.** Work in flight rebases after each merge (A11); the global lock (034.00) means this plan runs alone, so a long plan blocks everything else.
- **Behaviour drift** in the Dispatcher split (2,523 lines, 142 methods, 6 thread sites), the most likely place for a hidden ordering change. Existing `dispatcher_spec.rb` is the only guard.
- **`rubocop_todo.yml` paths** go stale when files move (CLAUDE.md): moved files must move there too.
- **Ordering with spans**: the A13 pull request depends on the dry-system providers and event bus being in place.
- **Coverage badge path** in `spec_helper.rb` points outside the repo: ignore it.
- **Dependency 049 to 052** are absent from `.plans`; the spec assumes they merged (their outputs `ol uml`, `docs/architecture/before/` exist). Unverified for 049 to 051.

## Conclusion

When this ships, `lib/` has no class over 100 lines or method over 10, `.rubocop_todo.yml` has no Metrics entries, components are wired through dry-system with providers for every external system, adapters resolve by name, no bare thread remains, and logs and spans come from one set of events. The CLI behaves exactly as before.
