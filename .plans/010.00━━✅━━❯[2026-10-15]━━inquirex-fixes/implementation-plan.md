## The contract F1 and F2 call (inquirex core)

| Interface | Shape | On failure |
| :-- | :-- | :-- |
| `Engine#back` | `-> Boolean`; restores the latest snapshot taken at a collecting step, stepping over display steps | `false`, nothing changed, before the first answer |
| `Engine#can_back?` | `-> Boolean` | none |
| `Engine#previous_answer(step_id)` | current answer, else the last one `back` took away | `nil` when never answered |
| `Engine#current_default` | current step's default, Proc resolved with answers so far | `nil` when finished or no default |
| `Inquirex::Headless.new(definition, answers:, yes:)` | `#call -> {path_taken:, answers:, steps_completed:}`; `#engine` for `after_completion` hooks | raises `Headless::MissingAnswer` (`Errors::EngineError`, `#step_id`) |

- The `back` stack is excluded from `to_state`; `from_state` starts with nothing to go back to.
- Headless feeds `answer` and `skip` only, never `prefill!`, never reads `$stdin`, never calls an LLM adapter. Preset values go to `answer` verbatim: no label canonicalisation, no splatting of an extract result. F2 adds `flow_file` and `completed_at` to the results.
- With `yes`: an unanswered step takes its resolved default; an optional one without a default is skipped; a required LLM step without one records `nil`. Without `yes`, optional steps left out are skipped and required ones raise `MissingAnswer`, even when they have a default.
