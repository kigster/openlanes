# Uml Class Diagrams

## What we are trying to achieve

`ol uml` prints Mermaid class diagrams of the project being built; `ol uml self` draws openlanes' own `lib/` (A10, A12). Classes only, no methods: directed edges for inherits, includes and uses, with `Data.define` value types folded into their owner. `ol uml` prints the namespace map, `ol uml <namespace>` one namespace, `-o FILE` writes a file. Source is parsed statically with Prism, never loaded. Neither draws `spec/`. `docs/architecture/before/` is generated once and frozen; `docs/architecture/` is regenerated by each refactor pull request, and a spec fails when it is stale.

## Why it matters

The refactor (045.00) needs a before and after picture of coupling, and agents get a map of the project they are building.

## What already exists

`lib/openlanes/presentation/diagram.rb` renders the state machine as Mermaid; `openlanes docs` and `docs/WORKFLOW.md` show the generated-and-checked pattern. Prism ships with Ruby 4.

## What research needs to settle

- How "uses" is detected statically: constant references, `Deps[...]` keys, or both.
- How Rails `app/` autoload paths map to namespaces.
